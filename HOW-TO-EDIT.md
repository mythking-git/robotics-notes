# How to edit and publish

## One-time setup
1. **Clone** the repo with GitHub Desktop to a local folder, e.g. `C:\Users\mikey\Projects\robotics-notes`. Not OneDrive, and not inside the private vault.
2. In Obsidian: **Open folder as vault** → choose `robotics-notes\content`.
3. Install **Git for Windows** (git-scm.com) and the **Obsidian Git** community plugin. Turn on *Pull on startup*.
4. Set the commit identity for this repo (GitHub Desktop → Repository → Open in Command Prompt):
   ```
   git config user.name "mythking-git"
   git config user.email "70135452+mythking-git@users.noreply.github.com"
   ```
5. Obsidian → Settings → Files and links: new attachments go in `assets`; link format "Shortest path when possible".

## Everyday workflow
1. Open the vault. Obsidian Git pulls the latest version.
2. Edit or add guides.
3. Ctrl+P → **Git: Commit-and-sync**.
4. GitHub Actions builds the site (about 2 minutes) and publishes it to the `site` branch. The server pulls it within 5 minutes, so it's live at https://notes.mythking.uk in about 7 minutes.

Check a build at https://github.com/mythking-git/robotics-notes/actions. A red ✗ means something in a note broke the build; click it to see which file.

## Where things go
```
content/
├── index.md           Home page
├── course.md          Course overview
├── about.md           About, AI note and tech stack
├── glossary.md        Every symbol and term
├── assets/            Diagrams (SVG)
├── templates/         Guide template (not published)
├── WM1AD/             One folder per module
│   ├── index.md       Module page: lists every guide
│   ├── Week 1/ …      One file per topic
│   └── WM1AD formula sheet.md
└── …
```

## Adding a guide
1. Copy `templates/Guide template.md` into the right module and week folder, and name it after the topic (e.g. `Centre of mass.md`). Names must be unique across the site, so links work with just the name.
2. Fill in each section. Use **your own numbers** in worked examples.
3. Add it to the module's `index.md`, and any new formulas to the formula sheet and symbols to the glossary.
4. Images: `![Description](../../assets/name.svg)` from a week folder, `../assets/` from a module folder. Always write a description.

## Writing syntax
| Want | Write |
|---|---|
| Link to a guide | `[[Mesh analysis]]` or `[[Mesh analysis\|custom text]]` |
| Inline maths | `$V = IR$` |
| Display maths | `$$P = I^2R$$` |
| Hidden answer | `> [!example]- Answer` then `> ` on each following line |
| Question with hidden answer | `> [!question]- 1. The question?` |
| Tip / warning box | `> [!tip]` / `> [!warning]` |
| Tags | `tags: [WM1AD, week-4]` in the frontmatter |

## Never publish
- Assessed work (portfolio drafts, reports, lab results) before marks are back, and preferably not at all
- Lecture slides, Moodle files, datasheet PDFs, quiz answers
- Anything private: work, clubs, other people's details, personal plans

## Preview locally (optional)
Install Node.js 22+, then in the repo folder:
```
npm ci
npx quartz build --serve
```
and open http://localhost:8080.

## Diagrams
Diagrams are generated by a Python script kept outside the repo. To add one, draw an SVG (any tool, e.g. Inkscape or draw.io, exported as SVG with a white background) and save it in `content/assets/`.
